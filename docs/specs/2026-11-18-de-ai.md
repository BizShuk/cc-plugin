# De-AI: 去除 UI 的 AI 味 (Unslop Concept)

來源: [heydamir/unslop](https://github.com/heydamir/unslop) (作者 Damir Sokolovsky, CC BY 4.0, 引用或改編需標註作者並連回原 repo).
本文只整理其設計概念, 不是 unslop skill 的複本.

## 核心觀點

- `Vibecoded UI` (由 AI 隨手生成的介面) 會用同一套方式失敗: 每個表面都在發光, 每個 label 都配 emoji, 間距沒有規則, 文案都在喊口號.
- 差別在 `richness 放在哪`. Slop 把色彩與特效撒在 chrome 上 (背景, 按鈕, 邊框, label). Craft 讓 chrome 保持安靜, 只把 richness 集中在 1-2 個內容 `moments` 上, 例如一張精心繪製的 chart, 一個有材質的物件, 或一張來自產品世界的圖.
- 去 AI 味只完成一半. 清乾淨卻放到哪個產品都通用的畫面, 只是下一個 template. 最終目標是一個 `只屬於這個產品` 的畫面.
- 修的是工藝, 不是產品: 功能, 內容與 section 順序保持不變. 變的是每個尺寸, 顏色, 字詞與圖片都變成有意識的決定.

## 好的畫面長什麼樣

- `One bright element`: 每個畫面只有一個精緻元素承載色彩, 周圍保持安靜.
- `Quiet chrome`: 導覽, 按鈕, 文字只用 tinted neutral (帶色調的灰階) 加一個 accent, 沒有任何元素發光.
- `A clear idea`: 能用一句話說出 visual 呈現什麼, 以及它為何屬於這個產品.
- `Text on calm space`: 標題放在刻意留白處, 一個 primary action 加至多一個 secondary action.
- `Real product, real material`: preview 看起來像真的 app 並使用合理資料, 物件有重量, 光線與陰影.

## 流程

1. 觀察: 先 render 或截圖, 以使用者實際看到的畫面判斷, 不只讀 code.
2. Audit: 對照下方的 slop 特徵清單, 每個問題一行, 寫明位置.
3. 判斷程度:
   - `Heavy slop`: 跑完整流程.
   - `Light slop`: polish 模式, 只修 audit 找到的問題, 沿用既有品牌.
   - `No slop`: 直說, 最多建議 2-3 個附確切數值的小調整.
4. 寫 Direction 後 `先停下來`, 等使用者確認, 因為方向改了就要全部重做.
5. 依序跑 9 個 pass. 每個 pass 都套用到整個畫面, 才進下一個.
6. 跑 checklist, 再 render 一次, 與 audit 清單比對.
7. 回報 direction 與每個 pass 改了什麼.

## Direction (5 行)

方向從產品本身推導, `不從潮流推導`.

| 欄位      | 內容                                     | 例子                                           |
| --------- | ---------------------------------------- | ---------------------------------------------- |
| Product   | 做什麼, 給誰, 一句話                     |                                                |
| Character | 2-3 個具體形容詞                         | `calm, exact, a little warm`                   |
| World     | 產品天然所屬的場所或材質, 決定色調與圖像 | 筆記 app -> 紙與墨; 監控工具 -> 儀表與夜班     |
| Moments   | 1-2 個允許豐富色彩的位置                 | 一張主 chart, preview 裡的一張實體卡片         |
| Signature | 一個只有這個產品才有的細節, 一致地使用   | 監控工具的 live status dot, 開發工具的 keycaps |

Character 禁用 `clean / modern / sleek / minimal / premium`, 因為這些詞每個 template 都適用.
真正的品牌 (logo, 顏色, 字體) 要保留, 但紫藍漸層, sparkle 與 glow 即使在 logo 上也不算品牌.

## 9 個 Pass (順序固定)

順序的理由: 先把節奏定好, 其他層才看得準; 文案長度決定字級與位置, 所以 Copy 在 Type 之前; Visuals 與 Motion 最後才加, 套在一個沒有它們也能成立的畫面上.

1. `Spacing`: 全部對齊 4px grid. 相同的東西用相同尺寸. 群組內間距小於群組間距. icon, label, 數字各自對齊成一欄. 移除 `mt-[13px]` 這類零散值.
2. `Color`: 一條帶世界色調的 neutral ramp; 三種文字角色 (primary, secondary, muted); 一個 accent, 少量使用. 移除 hue gradient, 漸層字, 彩色 glow, blob. 邊框用 6-10% 透明度的 hairline. App 的背景要保持中性.
3. `Icons`: emoji 換成同一套 line icon (預設 lucide), 16-18px, stroke 1.5, 顏色跟隨文字角色.
4. `Copy`: 標題寫出產品為誰做了什麼. 不用驚嘆號, 不用問候標題, 不用 hype 詞. 數字變化標明比較基準, 例如 `+12% vs last month`. 無法查證的宣稱先問是否屬實, 不實就移除.
5. `Type`: 依 Character 選字體; 只用 400/500 兩種字重 (600 罕用); hierarchy 靠字級與顏色; 全面 sentence case; 數字用 `tabular-nums`; 不用斜體.
6. `Layout`: 保留 section 與順序. App 維持真實比例 (sidebar 240-280, 內容寬度上限約 1440-1600). Landing hero 優先用 scene 或不對稱分割, 避免全部置中堆疊.
7. `Details`: nested radius (內層圓角 = 外層圓角 - padding). 數量與 meta 用安靜的 mono 文字. chart 要有主次, 一個 chart 只用一個 accent. stat card 只放數字, label 與變化值. 卡片寬度要有節奏變化.
8. `Visuals`: 移除裝飾性填充 (glossy blob, 星雲, 機器人, 全息大腦). Hero 展示產品本身或一個具體隱喻. Dashboard 幾乎不需要生成圖.
9. `Motion`: 移除無意義的循環動畫 (`animate-pulse`, shimmer), `transition-all` 與 `hover:scale`. 只保留能解釋狀態的動態. 全畫面一條 easing curve, 只 animate transform 與 opacity.

## Slop 特徵清單 (Audit 用)

| 類別     | 特徵                                                                 | 替換                                     |
| -------- | -------------------------------------------------------------------- | ---------------------------------------- |
| 色彩     | 紫 -> 藍 / 紫 -> 粉漸層, 漸層字, 彩色 glow, glass card, 五種淡紫文字 | 單一 neutral 表面 + 一個 accent          |
| 字體     | 800-900 字重標題, `NAVIGATION` 大寫加寬字距, 數字格式混用            | 400-500 字重, sentence case, tabular     |
| Icon     | emoji 當導覽或狀態 icon, AI 功能都配 sparkle ✨                      | 同一套 line icon, 或不放 icon            |
| 間距     | 任意 px 值, 同列表的列高不一, 兄弟卡片 padding 不同                  | 4px scale, 同類同尺寸                    |
| 文案     | `Welcome back! 👋`, `!!`, `Supercharge your workflow with AI`        | 頁面名或期間當標題, 說清楚做什麼         |
| 元件     | 發光 pill, `New ✨` / `PRO` badge, 彩虹 chart, 每張 stat card 都有 sparkline | 安靜文字或 keycap, 一張主 chart          |
| Landing  | `✨ Introducing` badge, 背景 orb, 3 個以上按鈕, `Trusted by 10,000+` | 真實 product view, 1 個主要 + 1 個次要按鈕 |
| Visuals  | 3D blob, 液態金屬, 圖裡烤進假文字, 每個 section 都有一張圖           | 產品本身, 只在 hero 放一張               |
| Motion   | pulse / ping, bouncy spring, 元素從四面八方飛入, parallax            | 靜態, 一次短促的 fade-and-rise           |

## 防止改過頭 (Template Look)

清完 slop 後最常掉進的預設狀態也要檢查:

- 純灰 `#161616` 背景 + Inter + 白字 + 一顆舊品牌色按鈕 -> 改用帶世界色調的 ramp, accent 取自世界.
- 換掉產品名後仍適用其他產品的標題 -> 改用這個產品自己的名詞.
- 空盒子或通用圖片當 hero -> 改用 code 寫的 product preview, 或來自產品世界的圖.
- 不要用新裝飾取代被移除的裝飾 (glass, grain, noise, neon, bento grid 只是換一種潮流).
- 不要發明功能, 宣稱或資料; 不要改產品名.

最後一道檢查 (`Template check`): 把產品名換成別家產品, 畫面還成立嗎? 若成立, 就在 copy, visual 與 signature 上把 direction 推得更深.
