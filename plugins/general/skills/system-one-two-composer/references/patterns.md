# 組合模式 (Composition Patterns)

每個模式都包含：結構、適用時機、為什麼有效、常見陷阱。
符號：`CODE` 程式、`S1` Jev、`S2` 一般 LLM、`HUMAN` 人工、`[...]` 同一次呼叫內並行。

---

## P1 — S1 單獨判斷

```
state → S1 [q1, q2, q3 ...] → CODE 依機率分支／排序／門檻 → 動作
```

- **適用**：客訴分類、緊急程度、情緒判斷、內容審核等，每個判斷都是「一眼就知道」。
- **為什麼有效**：全部題目一次並行，延遲幾乎不隨題數增加。
- **陷阱**：把需要計數或比較的題目也塞進來；忘了加「以上皆非 (none)」選項。

## P2 — 提早出口串接 (Early-exit cascade)

```
state → S1 [分類, needs_reasoning, 相關判斷...]
          ├─ 簡單 + 高信心 → S1 的答案直接使用 → 結束
          ├─ 低信心／可疑 → HUMAN
          └─ 需要推理 → S2 → (建議接 P5 覆核)
```

- **適用**：呼叫量大，而且多數案件簡單的流程（客服、工單、審核）。
- **為什麼有效**：只有少數案件付 S2 的成本與延遲。
- **陷阱**：沒先驗證就開啟提早出口。上線前先「只記錄不分流」，比較 S1 與 S2 答案的一致率。
- 官方參考：SDE cascade、intent routing。

## P3 — 投機式展開路由 (Speculative fan-out routing)

```
state → S1 [route, 分支A參數1, 分支A參數2, 分支B參數1, ...]
      → CODE 依 route 選分支，只讀取該分支的參數答案 → 呼叫對應函式
```

- **適用**：自然語言轉函式呼叫 (function calling)、多種處理者的分流。
- **為什麼有效**：多問的題目幾乎不增加時間，省下第二次呼叫。
- **陷阱**：投機題的前提沒寫清楚。題目要寫成「如果使用者要轉帳，轉出的帳戶是哪一個？」，而不是只寫「哪個帳戶？」。

## P4 — 檢索 → S1 過濾排序 → S2

```
query → CODE 檢索 (BM25／向量) 前 30–100 筆
      → S1 [每筆一題：相關性 Score、是否含注入 Noul、是否矛盾 Noul]
      → CODE 排序、過濾、取前 N
      → S2 推理／生成答案
```

- **適用**：RAG、研究助理、知識庫問答。
- **為什麼有效**：S2 拿到的 context 更短、更乾淨，推理更專注，也擋掉提示注入。
- **陷阱**：S1 過濾太嚴格導致關鍵資料被丟掉。保留「低相關但未確定」的邊界案例，或讓 S2 可以要求更多資料。
- 官方參考：re-ranking、classifying RAG passages。

## P5 — S2 → S1 覆核 (Reason-then-verify)

```
S2 產生結論／草稿／動作建議
  → CODE 抽出要檢查的欄位與對應來源片段
  → S1 [檢查清單：有依據嗎？違反政策嗎？動作屬於哪一類？]
  → 高信心通過 → 執行；否則 → S2 重做或 HUMAN
```

- **適用**：S2 的輸出會觸發真實動作，或會直接給客戶看。
- **為什麼有效**：像藥師核對處方，不重新診斷，只依清單核對。
- **陷阱**：把整段推理丟給 S1 問「對不對」。S2 的文字很有說服力，錯的也寫得頭頭是道；只給 S1 需要核對的片段。
- 另一個陷阱：覆核與推理看的是同一份殘缺資料，會「一起錯」。高風險時加一題「所需證據在來源中找得到嗎？」。
- 官方參考：citation check、LLM guardrails。

## P6 — 三明治 (Sandwich)：S1 → S2 → S1

```
S1 入口（驗證 + 勾選子任務 + 提早出口） → CODE 檢索 → S1 過濾 → S2 推理 → S1 覆核
```

- **適用**：完整的端到端流程。是 P2 + P4 + P5 的組合。
- **陷阱**：過度設計。每個階段都要記錄通過率與攔截率；某階段幾乎 100% 通過，就考慮移除。
- **錯誤累積**：四個階段各 95% 正確，全對機率只有約 81%。每一階段的低信心都要就地攔截。

## P7 — 先產生候選，S1 挑選 (Select, not generate)

```
source → CODE（regex／parser）或 S2 列出候選值
       → S1 Choice「哪一個是 ___？」（包含「都不是」選項）
       → CODE 正規化該值
```

- **適用**：擷取 email、金額、日期、實體名稱；從技能庫或工具庫挑一個。
- **為什麼有效**：S1 不需要生成，也不會編造不存在的值。
- **陷阱**：候選清單漏掉正確答案，S1 就不可能選對。要檢查候選覆蓋率 (candidate coverage)。
- 官方參考：pre-parsed value extraction、skill suggestion、date extraction。

## P8 — 組合評分 (Composite scoring)

```
state → S1 [維度1 Score, 維度2 Score, 維度3 Score, 否決條件 Noul...]
      → CODE 加權公式 + 否決規則 → 總分／排名
```

- **適用**：候選人篩選、提案評估、內容品質分數、優先順序排序。
- **為什麼有效**：權重在程式裡，改優先順序不用重跑推論，也不用改提示。
- **陷阱**：「任何一項嚴重違規就否決」不能用加權平均表達，要另外寫成 Noul 條件。

## P9 — 階層分類／束搜尋 (Hierarchical / beam search)

```
第 1 層 S1 Choice → CODE 保留前 k 名
第 2 層 S1 [每個保留分支各一題 Choice]（並行）→ CODE 機率相乘，保留前 k 名
…直到葉節點；低信心時停在上一層較粗的類別
```

- **適用**：類別很多層或總數超過 255（產品目錄、專利分類、產業分類）。
- **陷阱**：k 太小會太早剪掉正確分支；k 太大成本上升。

## P10 — 大量資料轉特徵 (Map-reduce features)

```
N 筆文字 → S1（每筆同一組題目，批次並行）→ 表格欄位 → CODE 統計／傳統 ML（例如 CatBoost）
```

- **適用**：評論分析、問卷開放題、log 分類、爬蟲資料清洗。
- **為什麼有效**：S1 便宜又快，可以對每一筆都做語意判斷。
- **陷阱**：沒有人工標註樣本就直接相信統計結果；先抽樣驗證。

## P11 — S2 設計、S1 執行 (S2 designs, S1 runs)

```
離線：S2 根據目標與樣本，草擬 S1 題目、criteria、評分等級 → HUMAN 審核
線上：S1 用這組題目處理大量資料
定期：S2 分析 S1 的錯誤案例 → 提出題目修正 → HUMAN 審核
```

- **適用**：需要思考「該問什麼」，但執行量很大的任務。
- **為什麼有效**：S2 的思考只做一次，S1 負責重複執行。
- **陷阱**：S2 草擬的題目常常一題包含多個判斷、或 criteria 有反向定義；審核時用 SKILL.md 的反模式清單檢查。

## P12 — S1 監督 S2 代理迴圈 (S1 guards agent loop)

```
每一輪：S2 agent 提出下一個動作
        → S1 [這個動作屬於哪一類？是否超出任務範圍？是否不可逆？]
        → CODE：安全 → 執行；不可逆且低信心 → HUMAN；越界 → 退回 S2
```

- **適用**：coding agent、瀏覽器 agent、會呼叫工具的 agent。
- **為什麼有效**：每一步只增加約數百毫秒，卻能在動作發生前把關。
- **陷阱**：把整段 agent 歷史都當成 state；只送當前動作與必要的任務描述。
