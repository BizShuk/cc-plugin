# 設計範例

以下範例示範完整的推理過程。數字皆為示意，實際效益以實測為準。

---

## 範例一：客服退款申請

**目標**：自動處理退款申請；每天約 5,000 件；回覆延遲可以到數十秒；錯誤退款會造成金錢損失。

### 步驟分類

| # | 步驟 | 類型 | 理由 | 依賴 |
|---|---|---|---|---|
| 1 | 查訂單資料、付款紀錄 | CODE | Q1：資料庫查詢 | — |
| 2 | 計算是否在退款期限內 | CODE | Q1：日期運算 | 1 |
| 3 | 判斷申請原因類別（瑕疵／不喜歡／未收到／其他） | S1 Choice | 固定選項、一眼可判 | — |
| 4 | 客戶情緒與流失風險 | S1 Score | 有序等級、一眼可判 | — |
| 5 | 是否有附上證明、是否提到法律行動 | S1 Noul ×2 | 是非判斷 | — |
| 6 | 是否需要推理（例如多張訂單、條款爭議） | S1 Noul | 提早出口的關鍵題 | — |
| 7 | 複雜案件：依條款推理並草擬回覆 | S2 | Q2：需要生成文字、多步推理 | 1–6 |
| 8 | 覆核：回覆是否承諾政策外補償、動作類別 | S1 | P5 檢查清單 | 7 |
| 9 | 金額超過門檻或提到法律行動 | HUMAN | Q7：高代價 | 5, 8 |

### 組合

P2（提早出口）+ P5（覆核），整體接近 P6。步驟 3–6 放在**同一次** S1 呼叫；步驟 1–2 與 S1 同時進行。

```
申請 ─┬─ CODE 查訂單、算期限
      └─ S1 [原因, 情緒, 有證明?, 提到法律?, 需要推理?]
               │
   ┌───────────┼───────────────┬─────────────────┐
 簡單且高信心   需要推理        提到法律／高金額     低信心
   │           │                 │                 │
 CODE 依規則   S2 推理＋草稿      HUMAN            HUMAN
 退款＋範本回覆  │
               S1 覆核 ─ 通過 → 執行；未通過 → HUMAN
```

## 範例二：Pull Request 審查分流

**目標**：決定每個 PR 要走哪一種審查；每天約 200 個 PR；延遲要求低；漏掉安全問題代價高。

| # | 步驟 | 類型 | 理由 |
|---|---|---|---|
| 1 | 取得 diff、變更檔案清單、行數 | CODE | 精確資料 |
| 2 | 依檔案路徑判斷是否碰到 auth／payment 目錄 | CODE | 路徑比對即可，不需要模型 |
| 3 | 變更類型（文件／重構／新功能／修 bug／設定） | S1 Choice | 固定選項 |
| 4 | 對每個變更檔案：是否涉及權限、輸入驗證、機密資訊 | S1 Noul（每檔一組，並行） | 一眼判斷，逐檔拆開避免 context rot |
| 5 | 深度審查：找邏輯錯誤、寫審查意見 | S2 | 需要推理與生成 |
| 6 | 審查意見是否每條都對應到實際 diff 行 | S1 | P5 覆核，避免編造的意見 |

**組合**：P1（分流）+ P2（只有高風險 PR 進 S2）+ P5。純文件變更且高信心 → 直接標記為低風險，不送 S2。
**注意**：步驟 2 很容易被誤設計成 S1，其實 CODE 就能做到而且 100% 準確（決策樹 Q1）。

## 範例三：大量商品評論分析

**目標**：分析 50 萬則評論，產出產品改善報告；批次處理，延遲不重要；成本敏感。

| # | 步驟 | 類型 | 理由 |
|---|---|---|---|
| 1 | 設計要問的維度與評分等級 | S2 → HUMAN 審核 | P11：思考只做一次 |
| 2 | 每則評論：提到哪些面向（Noul 各一題）、各面向滿意度（Score）、是否為垃圾評論 | S1 | P10：大量重複判斷 |
| 3 | 統計、交叉分析、找出下降趨勢 | CODE | 數學與聚合 |
| 4 | 每個問題面向，抽出最具代表性的 20 則評論 | CODE 排序 + S1 Score 代表性 | P4 精排 |
| 5 | 撰寫改善報告 | S2 | 生成文字，只讀統計結果與代表評論 |

**組合**：P11 → P10 → CODE → P4 → S2。
**效益方向**：S2 只被呼叫兩次（設計題目、寫報告），50 萬則評論全部由 S1 處理。
**驗證**：先抽 300 則人工標註，檢查每個維度的準確率與依信心分桶的準確率，通過後才跑全量。
